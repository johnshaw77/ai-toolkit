# Handoff：跨機器 / 跨對話交接

這個 Skill 有兩個模式。先依使用者的話判斷是 **handoff**（交出去）還是 **resume**（接起來）；不確定就問一句。

**一個任務一份交接檔**：`handoff/<主題>.md`。使用者常在同一個 repo 同時開好幾個 Claude 處理不同任務，它們共用同一個工作目錄，所以交接檔要分開放、提交時只帶自己改過的檔案。

## 先判斷專案類型：私人還是公司

用 `git remote get-url origin` 看遠端網址：

- 網址含 `jnxstudio` 或 `johnshaw77` → **私人專案**（只有使用者一人）。
- 其他（或沒有遠端）→ **公司專案**（共用遠端）。

私人專案的清單就是上面這兩個字串；使用者有新的私人帳號再加在這裡。

| 動作 | 私人 | 公司 |
|---|---|---|
| 分支 | **不另開分支**，直接在目前分支（通常是 main）commit | 用 worktree 切出 `wip/` 分支提交，**不動目前的工作目錄** |
| commit | 自動 | 自動 |
| push | 自動推目前分支，不用問 | 只推 `wip/` 分支，先列出檔案，**等使用者說可以**再推 |
| 發現疑似機密 | 停下來問 | 停下來問 |

私人專案只有使用者一人、deploy 也只是留紀念或分享，不需要 wip 分支的隔離，也免得忘記收尾。公司專案不在原地切分支，是因為其他 Claude 共用這個工作目錄，切分支會連它們的檔案一起換掉。

任何情況都不要 force push、不要改寫已推送的歷史。公司專案不要 push 到 `wip/` 以外的分支。

## 模式 A：handoff（交出去）

目標：讓另一台機器上的全新對話，只靠 repo 就能無痛接手，並且不碰到其他 Claude 的工作。

1. **取主題（slug）**：
   - 這個對話是 resume 某份交接檔接著做的 → 沿用那份，直接更新它。
   - 否則依本次任務取簡短 slug：小寫英數與連字號、40 字以內，例如 `login-validation`。
   - `handoff/<slug>.md` 已經存在、而且這個對話沒有讀過它 → 那是別的任務，**不要覆寫**：換一個 slug（加 `-2`），並告訴使用者。
2. 用 `date '+%Y-%m-%d %H:%M'` 取時間、機器名稱讀 `~/.claude/host-badge.json` 的 `label`（host-badge mod 設的，例如 `Macbook Pro`），沒有這個檔才用 `hostname -s`，**不要憑印象寫**。不要用 `scutil --get ComputerName` 或 `LocalHostName`：它們常含真實姓名，不該寫進 repo。
3. **找出這個任務改過的檔案**：回顧本次對話，列出你建立、修改、刪除過的每個檔案。以這份清單為準，**不要用 `git status` 的全部內容**：裡面可能混著其他 Claude 的變更。
   - 用 `git status --porcelain` 對照：清單裡的檔案要確實有變更；沒有的就拿掉。
   - 對清單裡每個檔案看 `git diff <檔案>`：如果裡面有不屬於這個任務的改動（別的 Claude 也改了同一個檔案），**停下來問使用者**，不要自己拆。
   - 其餘有變更、但不在清單裡的檔案**不要碰**，最後回報時說有幾個沒納入就好。
4. 在 repo 根目錄的 `handoff/` 寫（或更新）`<slug>.md`（資料夾不存在就建立），使用下方固定格式。內容要具體到檔案路徑與指令，不要寫「大致完成」這種模糊說法；「相關檔案」就是上一步的清單。
5. **機密檢查**：
   - 一律排除：`.env*`、`*.pem`、`*.key`、`id_rsa*`、`docs/transcripts/`，以及 `.gitignore` 已經擋掉的東西。
   - 用 `git diff` 掃清單裡的檔案與交接檔，找 `api[_-]key|secret|password|token|BEGIN.*PRIVATE KEY`；有命中就停下來問使用者，不要自己判斷是不是誤報。
6. **提交**（commit 訊息用繁體中文，技術名詞與識別字保留原文）：
   - 私人專案：`git add <清單裡的檔案> handoff/<slug>.md`，**逐一指定路徑，絕不 `git add -A`、`git add .`、`git commit -a`**。訊息 `交接：<主題> - <一句話描述>`，用 `git commit -m ... -- <同一批路徑>`，確保別的 Claude 剛 add 的東西不會被帶進來。
   - 公司專案：不要在原地切分支。
     ```bash
     git worktree add -b wip/<slug>-<YYYYMMDD> "$(mktemp -d)" HEAD
     ```
     把清單裡的檔案（含交接檔）複製進那個 worktree，已刪除的用 `git rm`，在裡面 add、commit，訊息 `wip：交接 - <主題> - <一句話描述>`。完成後 `git worktree remove` 那個目錄。目前的工作目錄與分支維持原樣。
   - 遇到 `index.lock`（別的 Claude 剛好也在 commit）：等 3 秒再試，最多 3 次；還是不行就告訴使用者。
7. **push**：依上面的表格——私人直接 `git push`，公司先問，且只推 `wip/` 分支（`git push -u origin wip/<slug>-<YYYYMMDD>`）。沒有遠端就只 commit，並告訴使用者。
   - 被拒絕（別的 Claude 先推了）：私人專案用 `git pull --rebase --autostash` 再推一次。這只重放你剛做的那筆 commit，不會改到別人的歷史；但 autostash 會**短暫**把其他 Claude 尚未提交的變更收起來再還原，所以只在被拒絕時才做、做完立刻確認 `git status` 沒有衝突。還原出現衝突就**停下來告訴使用者**，不要自己解。
8. 回報：專案類型、分支名稱、commit hash、有沒有 push、交接檔路徑、**有幾個變更沒納入**（屬於別的任務），以及另一台機器上該下的指令：

   ```bash
   # 私人（目前分支，通常是 main）
   git pull --ff-only
   # 公司（wip 分支）
   git fetch --all --prune && git checkout <wip 分支> && git pull --ff-only
   ```

### handoff/<主題>.md 格式

第一行標題與第二行的資訊列要照這個格式寫，resume 列清單時會用它們。

```markdown
# <任務標題，一句話>

> 更新：<日期時間>｜機器：<機器名稱>｜分支：<分支>｜主題：<slug>

## 目標
<這個任務最終要達成什麼>

## 目前進度
- 已完成：...
- 進行中：...（做到哪個檔案、哪個函式）

## 相關檔案
- <路徑> — <改了什麼>（建立／修改／刪除）

## 已做的決策與原因
- 決策 → 原因（這是最容易遺失、最重要的一段）
- 專案若已有 docs/DECISIONS.md，這裡只放連結與一句話，不要複寫一份

## 試過但失敗的做法
- 做法 → 為什麼不行

## 下一步
1. ...
2. ...

## 風險與未提交內容
- 有問題或尚未驗證的變更、相關檔案路徑
- 最後一次跑的測試／型別檢查：指令與結果（綠或紅、哪幾個失敗）；沒跑過就寫「沒跑過」

## 環境注意事項
- 需要啟動的服務、埠號、環境變數、尚未跑的 migration、測試指令
- repo 帶不走、要先用 media-sync 等工具同步的檔案（媒體、素材、gitignored 但需要的檔案），寫出是哪些、放哪裡
```

## 模式 B：resume（接起來）

目標：快速恢復脈絡，並在動手前先確認理解正確。同一個 repo 可能有好幾份交接檔，由使用者決定接哪一份。

1. **拿到最新內容**：
   - 私人專案：`git pull --ff-only`；失敗（本機與遠端分歧，或有檔案和本機未提交的變更重疊）就停下來告知，不要自己 merge 或 reset。
   - 公司專案：交接檔在 `wip/` 分支上，新機器預設不在那裡。先 `git fetch --all --prune`，用 `git branch -r --sort=-committerdate --format='%(refname:short) %(committerdate:relative)' | grep 'wip/'` 列出最近的 `wip/` 分支。要切換分支前先看 `git status`：本機有未提交變更就停下來問，不要硬切。切過去後 `git pull --ff-only`；失敗就停下來告知。
2. **列出交接檔讓使用者選**：
   - 讀 `handoff/*.md`，每份取第一行標題與第二行資訊列（更新時間、機器、分支），再加上 `## 目標` 的第一句。
   - 用表格列出，第一欄是靠右的 `#` 流水號：

     | # | 主題 | 標題 | 更新 | 機器 |
     |---:|---|---|---|---|

   - 使用者剛才說的話明確對得上某一份（例如「接續登入驗證」）→ 直接選它，並說明選了哪份、為什麼；對不上或有兩份以上都像 → 列表請使用者挑，**不要猜**。
   - 只有一份也要說「找到一份：<主題>」再繼續，不要默默讀。
   - `handoff/` 不存在或是空的：看根目錄有沒有舊格式的 `HANDOFF.md`，有就當成唯一一份；都沒有就告知使用者，並改問他目前進度。
3. 讀選定的那一份，再核對：
   - 只看它「相關檔案」裡列的檔案：`git status`、`git log --oneline -5 -- <那些檔案>`，對照目前分支是否與資訊列一致、檔案狀態是否和文件說的相符。
   - 其他不在清單裡的變更屬於別的任務，**不要碰、也不要當成不一致**；最多說一句有幾個。
   - 「環境注意事項」裡要先同步的檔案（media-sync 等）也要確認這台有了。
4. 用 3～5 句話回報：「我理解的目標、目前進度、下一步」，並指出任何不一致之處。
5. **等使用者確認後才開始修改程式碼。**
6. 完成後的收尾：問使用者要不要刪掉這一份交接檔（或更新它）。**只處理自己這份**，其他交接檔不動。刪除用 `git rm handoff/<slug>.md` 並提交（`交接：完成 <主題>，刪除交接檔`），一樣只帶這個路徑。公司專案要特別提醒：**合併回主線前要先刪掉 `handoff/` 底下的交接檔**，並在合併後刪除 `wip/` 分支，避免過期的交接文件進到主線。私人專案沒有這個問題，但過期的交接檔還是會誤導下一次對話，順手更新或刪掉。

## 原則

- 長期不變的專案規則屬於 `CLAUDE.md`，不要寫進交接檔。
- 不要在交接檔放密碼、token、連線字串等機密。
- 交接檔是暫時的：用完就刪或更新，不要累積成歷史（歷史交給 git log）。
- 共用工作目錄時只動自己的東西：只 add 自己的檔案、只刪自己的交接檔、不碰別人的未提交變更。
